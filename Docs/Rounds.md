# ラウンドと時計

対戦は各最大 180 秒のラウンドで、最大 3 ラウンドです。Bot 戦でも人同士の対戦でも、1 キルでラウンドが終了し、倒した側に 1 勝が入ります。制限時間までキルがなければそのラウンドは引き分けです。先に 2 勝した側が試合に勝ち、3 ラウンドを消化しても 2 勝に達しなければ試合は引き分けです。

1人で参加すると、本人の校正と追跡が有効で Bot の準備が整った時点で、管理者の開始操作を待たずに初回の試合が始まります。**ログインだけでは校正されません。** 一時停止中や試合終了後に勝手に開始・再戦することはありません。

本人の校正は、プレイヤーとして接続した後に次の操作を行います。

- **Quest:** パススルーと頭部の位置追跡が動作している状態で、床の基準となる目印に立ち、決めた正面を向いて左コントローラーの **Y** を押します。接続済み ContactGlove の左手の A ボタン入力が有効な場合も、同じ校正を行えます。
- **Windows のデスクトッププレイヤー:** `-MRFPSDesktop` を指定して起動し、ゲーム画面にフォーカスした状態で **C** を押します。`device_login.py windows` からの起動にはこの指定が含まれています。F1 のプレイヤーメニューにある「原点登録」でも操作できます。

Quest の本人校正は、その端末で現在確認できる頭の位置・向きと Stage 床を基準にします。1人用に作られる Bot の配置はこのプレイヤー向けの配置であり、別の Quest との共有原点を登録したことにはなりません。2人目が入ると Bot が退場して勝数などがリセットされ、2人用の条件を満たすまで待機します。Quest 2台の場合は、それぞれ同じ実床の目印と正面で本人校正を行い、管理者が共有原点の「原点登録」と「床の位置調整」を行ってください。詳しい条件は [管理と床の校正](AdminLayout.md) を参照してください。

一時的に姿勢データが途切れても同じ校正が有効な場合は、Bot 戦を一時停止し、追跡が戻って準備が整うと再開します。ヘッドセットの追跡喪失や再中心化などで校正が無効になった場合は、本人が再校正してください。校正世代が変わると Bot を作り直して試合をリセットします。管理者が明示的に一時停止した場合は、自動では解除しません。

1人用で「障害物スキャン未受信」と表示されている間は、実空間の障害物はまだサーバーの判定に反映されていません。画面上の仮想オブジェクトの判定は使用されます。上記の Quest 操作や実測障害物の反映は、実機での確認が別途必要です。

試合終了後は自動で再戦しません。管理者が開始を選ぶか、選手の入れ替えによって待機状態に戻したうえで、新しい試合を開始します。

ラウンド終了時は勝敗を視界の中央に大きく表示し、Quest の左 Y（Windows は Y）を押すまで待ちます。Bot 戦は本人が押すと、1 対 1 は両者が押すと、中央のゲージ付き 3・2・1 が始まります。2 勝先取または最大 3 ラウンドで試合が終わった後も結果を表示し、同様に準備が揃えばスコアをリセットして次の試合を開始します。各ラウンドのカウントダウン中は射撃、シールド、壁設置などの戦闘操作を受け付けません。180 秒の制限時間はカウントダウン終了後から始まります。次のラウンドの開始時にキル・死亡数、HP、弾数とプレイヤーが作った壁をリセットします。管理者が設置した壁や箱は残ります。管理者の一時停止中は結果表示、カウントダウンとラウンド時計も止まり、再開時に期限を延長します。管理者リセットや選手の入れ替えではラウンド勝数と準備状態も消去します。

Quest は頭に追従する中央上の表示、Windows プレイヤーは画面中央上の表示で、残り時間とラウンド番号、自分と相手の勝数を確認できます。 観戦のメイン画面と別観戦窓も中央上にラウンド番号、残り時間、P1/P2 の勝数を表示します。時間はサーバーが管理し、各クライアントは複製された期限とサーバー時刻から表示を計算します。`tools/automation/control.py` の `status` は同じ状態を読み取れます。

サーバー、Quest、Windows、Mac は network protocol **17** にそろえてください。旧 protocol 16 のサーバー・クライアントと混在接続はできません。実配布には各プラットフォームの再ビルドが必要です。

`MRFPS.Match.ThreeRoundRules` はゲーム内の権威側状態を使い、180 秒の初期値、1 キルでのラウンド終了、停止・再開、各ラウンドの勝敗、引き分け、2 勝と選手入れ替え時のリセットを検証します。テスト中に期限を調整するため、実際の 180 秒の運用や Quest 上の見え方の確認を代替しません。

`Scripts/Test-DeviceRoles.ps1 -Scenario solo-bot` は新しい専用の run directory、プレイヤーのいない `bRequireAdminStart=True` の検証用コンテナとその fingerprint、対応する Windows クライアントを指定して実行します。コードは管理 Worker で新規交換し、対象プロセスだけをメモリガード下に起動します。最初の desktop player と Bot、ラウンドの時計、実測メッシュ未受信の表示、次の人間による Bot 退場と勝数・共有床登録の初期化を検査します。レポートには起動した実行ファイルのパスと SHA-256 も残ります。これは Quest のトラッキングや実際の障害物スキャンの成功を証明しません。
